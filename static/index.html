PAHAMI ALGORITMANYA

Bukan mencari jam paling benar.
Mencari waktu yang disepakati.

Berkeley menyelaraskan jam di dalam kelompok. Tidak ada acuan UTC dari internet, sehingga jam yang sudah seragam belum tentu sama dengan waktu resmi.

  1. Koordinator meminta jamClient membalas waktu virtualnya melalui koneksi TCP.
  2. Hitung offset dan rata-rataPerkirakan waktu balasan dengan RTT/2. Abaikan outlier, sertakan offset koordinator sebesar 0.
  3. Kirim koreksi yang berbedaKoreksi client = rata-rata − offset client. Koordinator juga menyesuaikan jamnya sebesar rata-rata.
  4. Amati hasilnyaJam menjadi hampir sama. Sisa perbedaan kecil dapat terjadi karena delay jaringan tidak simetris.
Contoh hitung yang bisa dijelaskan saat presentasi

Offset koordinator = 0, client A = +20, B = −10, C = +35 detik.

Rata-rata = (0 + 20 − 10 + 35) / 4 = +11,25 detik.

Koreksi: koordinator +11,25; A −8,75; B +21,25; C −23,75 detik. Setelah dikoreksi, semuanya berada sekitar 11,25 detik di depan waktu awal koordinator.

Ini simulasi jam virtual dengan proses client dan komunikasi TCP nyata. Koreksi negatif langsung memundurkan jam virtual; sistem produksi biasanya memperlambat jam secara bertahap (slewing).
